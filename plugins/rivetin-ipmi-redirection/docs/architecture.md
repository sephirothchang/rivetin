# IPMI 插件设计与接入边界

## 现成 Island 的用途

调查到的 `hostIsland` 提供集群管理常驻弹窗，`vmIsland` 提供虚拟机视图，`clusterVersionIsland` 提供版本组件。它们是实现方式的参考，不能直接变成 IPMI 跳转插件。

Rivetin 框架注册在全局常驻区域，本插件通过框架的描述文件与子插件工厂加载。框架拥有统一配置入口与外层面板；插件提供自己的设置组件、配置 store 和激活/清理逻辑，并通过 MutationObserver 增强主机概览的 IPMI 字段。没有修改主界面资源文件，也没有替换现有模块。

## 浏览器增强

IP 字段识别结合主机路由、概览视图、`copy-icon-wrapper`、`copy-content` 和同级 IPMI 标签，拒绝不合法地址、对话框及多个候选字段。只把 IP 文本包装为链接，保留相邻复制按钮；观察重绘后重新匹配，卸载时还原当前文本。点击时再次校验主机 ID，避免路由变化到下一次扫描之间跳到旧主机。

每次激活重新读取资产清单，并以请求序号隔离旧激活结果。停用期间结束的请求不能覆盖重新启用后的状态；未确认当前主机存在于清单时，不能将其集群上下文视为已知。异步模拟登录在请求前及响应后再次检查生命周期、主机、地址和已保存登录规则，失效时关闭预开窗口并停止导航。这些保护不授予真实 BMC 登录能力。

框架负责菜单注入、悬浮入口及统一面板；菜单通过“设置”分组中的标签管理项定位，兼容只读观察到的 `div.menu-group-item` 结构。新增按钮为框架拥有的节点，不复用原菜单项事件。两处入口共享框架的 React 状态和面板，IPMI 插件不另建一套。

## 偏好和 BMC 规则

配置分为浏览器个人偏好与服务端功能配置。悬浮按钮显隐、拖动位置等个人界面偏好保存在浏览器，按浏览器、站点来源隔离。功能配置通过 Rivetin 统一 API 共享，不按浏览器或管理账户拆分；同一插件以最后成功保存的版本为准。

配置只允许布尔开关、已知厂商 ID、范围和资产 ID，不接受密码、令牌、任意 URL 或任意脚本。最多 2000 条例外，同范围同对象去重。读取集群后自动为每个新集群生成一条例外草稿，保存后共享；记录已处理集群 ID，防止删除规则后反复生成。超过容量时明确报错，不静默截断。

设置面板编辑草稿，跳转增强器只使用已保存配置。取消退出保留草稿，丢弃恢复服务器已读版本，保存并退出仅在确认保存成功后关闭。保存响应不确定时读取服务器核对，不自动重发写操作。独立客户端编辑同一插件时，后保存者覆盖该插件完整配置；其他插件不受影响。

原型服务仅在本地监听，文件写入串行化并通过临时文件、同步和原子重命名保存，重启后可读。正式 Island 未接入真实后端时禁用功能编辑和保存，不回退为浏览器保存。接口、身份与权限接入边界见 [共享配置 API](../../../docs/rivetin-configuration.md)。

匹配顺序固定：主机例外 → 集群例外 → 全局默认。规则顺序不决定优先级。存在集群规则但无法确认主机归属时，停止自动适配，仍允许普通链接跳转。空对象规则视为未完成。

厂商选项表示协议适配器标识。全局默认使用通用 BMC，新建例外默认选择集群；已保存的明确选择不被覆盖。目录收录 SmartX HCL 的全部 29 家厂商和 158 条型号记录，并额外保留 AMI 与通用选项。

10 家有公开依据的厂商配置共用 Redfish 会话客户端，支持资源发现、登录、设备摘要读取和自建会话退出；通过显式模拟传输验证，尚未连接真实设备。只有 MegaRAC 保留本地模拟网页会话链路，其他厂商不能被描述为已完成网页自动登录。型号清单不证明具体 BMC 固件兼容，详见 [BMC 接口接入说明](bmc-interfaces.md)。

资产信息通过主界面传入的 Apollo Client 查询可见的集群、主机 ID/名称和归属关系，不查询凭据。正式接入时须验证当前版本 GraphQL 契约与用户权限；本地演示使用独立的假资产数据。

## 普通跳转

正式构建只根据 IP 字面量形成 `https://<IP>/`，不获取任何凭据。演示构建把目标映射到本地模拟登录页，不能被误认为已经访问真实 IPMI。

## MegaRAC 自动登录

目标设备静态代码显示原生页面向 `/api/session` POST 表单用户名/密码，然后使用 CSRFToken 和其他响应字段建立浏览器页面状态。服务端取得会话不等于浏览器已登录；Tower 和 BMC 的存储来源不同。

本地模拟采用独立网关来源：

1. Island 发送演示主机 ID 和协议 ID；网关拒绝任意目标 URL、未知主机或未适配协议。
2. 网关生成 30 秒有效、只能使用一次的不透明启动票据。
3. 新窗口访问启动票据，网关调用显式注入的假 BMC 传输层；绝不默认回退到真实网络。
4. 网关在自身来源下设置 HttpOnly 会话 Cookie，并由引导页面写入模拟 BMC 会话状态。
5. 演示控制台同时检查网关会话与 CSRF，显示模拟登录结果。会话五分钟失效；缓存有数量上限。

这验证的是浏览器来源下建立会话的模型，**没有代理真实 AMI 页面**。完整生产网关仍需处理页面和静态资源 URL、跳转、Cookie、请求头、WebSocket/KVM、证书验证与注销。不能从模拟结果推断这些已兼容。

真实接入必须让服务器根据当前 Tower 用户身份重新校验目标主机权限，并将客户端的偏好协议与服务器资产映射核对。不能把本地偏好或客户端 hostId 直接当作访问凭据的授权。凭据读取和解密仅位于受控后端，不进入 Island 构建、地址参数、日志或浏览器持久化存储。

强制改密分支、认证失败、超时和未知响应均停止，不自动改密或无限重试。正式构建未接入网关时不启用自动登录。

## 后续仍需完成

- 扩展其他 Tower 版本、非管理员原生角色和更多页面布局的专项验证；当前测试版已验证主机 IPMI DOM、管理身份和紧急禁用清理。
- 验证真实资产查询和 Tower 用户身份到凭据代理的授权传递。
- 单独验证真实 MegaRAC 固件的会话建立、页面代理和注销。
- 确定按用户/租户隔离的网关域名及会话、目标白名单、凭据读取方式与审计策略。
- 测试插件包安装、回滚和 Tower 升级兼容性；0.1 已执行框架与子插件安装及基本真实页面验收；多版本升级和真实硬件仍需专项验收。
