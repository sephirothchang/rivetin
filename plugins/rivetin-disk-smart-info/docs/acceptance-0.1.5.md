# 0.1.5 候选验收

本版只修复读取失效的固定错误保留与恢复提示，不新增后台采集或 v2 设备策略。源码、固定候选、部署和市场版本须分别核对；本说明不代表已经执行真实验收。

## 本地验证

在插件目录使用现有 Node.js 22+ 工具链运行：

```powershell
node --test tests/provider.test.js tests/ui.test.js
npm test
npm run build
npm run package
npm run verify:package
```

打包仅能创建不存在的新版本文件。同版已有文件时明确失败，不能删除或覆盖它继续打包。验收前核对 `release/rivetin-disk-smart-info-0.1.5.rivetin.json` 的摘要；0.1.3、0.1.4 原包摘要和历史前端字节关系由包验证检查，不能重打旧版基线。

本地演示通过 `npm run demo` 监听 README 所列回环地址。在本角色新建的内置浏览器标签中选择“绑定变化”“盘权限撤销”“会话失效”“插件停用”，打开 Smart 信息，再切换中英文。期望只显示固定恢复提示，不显示先前指标、历史或服务端异常文本，立即采集禁用。恢复正常场景可重新读取；切盘及退出清理旧展示。再核对虚拟盘明确标注示例、真实健康未知且不能采集，物理盘失败不冒充认证失败或坏盘。

框架 0.2.1 冻结后，本地 v2 消费链可单独运行 `node --test tests/v2-provider.test.js`，或随 `npm test` 运行。该用例覆盖真实后端模块与共享 HTTP 的连接，库存和命令结果仍为替身；不作为真实环境、网络或物理盘验收。测试及文档新增不改变已固定包的运行字节。

演示、jsdom 和本地 HTTP 中的 Tower/SSH 替身均不能作为真实样本或 v2 后端接通的证据。

## 真实窗口与下一门槛

由协调方冻结框架与插件版本、摘要、准确目标、文件/配置备份和回退方式，串行安排部署。保持旧固定包，不恢复旧审批；运行窗口不以虚拟机快照作为门禁。

1. 在内置浏览器核对目标 CloudTower 构建、实际插件版本、集群/主机物理盘侧栏、语言切换、插件启停和原生内容恢复。记录页面证据及对应状态回读。
2. 仅在明确授权的目标上验证实际可信绑定、对象读取权限和人工批准。若遇到绑定变化、会话失效或插件停用，记录实际固定错误及界面清空/禁采集；缺少可安全复现条件的错误场景注明未验证，不为制造错误任意改权限或真实设备。
3. 实际 SMART 采集须取得匹配物理身份、已脱敏的有效健康属性及持久化终态；SSH 认证成功、命令退出、虚拟盘示例、旧采样和 HTTP 成功均不能代替本次真实结果。失败保持健康未知，并分别检查 SSH 独立认证结果与读盘结果。
4. all/custom 的空集、库存变化、同路径换盘、审批撤权和历史隔离须依据框架实际后端另行验证，前端不传设备路径、序列号或命令。每次手动操作最多提交一次；未知结果先只读回查。
5. 每日采集只有在框架具备合法后台库存身份、fresh 校验和跨日持久证据后才能标通过；`daily-smart/86400` 声明及 `scheduled=false` 不等于任务运行。缺少身份时保持拒绝后台执行。

任何必需实测失败，登记问题并回到开发及受影响测试。候选字节变化后重新冻结、部署与实测。已验证、待真实环境测试、实际失败分别记录；纯缺真实条件不阻断发布或已授权部署，不能伪称通过。实际失败、数据保护和准确授权仍具体处理；提交发布仍需脱敏、制品审核和官网回读。
