# SMART 命令声明与逐盘执行计划

## 范式不等于固定设备

0.1.6 的命令声明使用以下说明性模板：

```text
sudo -n -- /usr/sbin/smartctl --json=c --all <disk>
```

目标类别是 `disk`，参数来源要求是当前目标主机的新鲜库存，展开方式是每个授权盘各一条计划。`<disk>` 不作为 shell 参数直接执行，也不是管理员可编辑的命令。具体 `/dev/sdb` 可以是一条合法单盘计划；它不能代表整个插件只支持这一块盘。

本插件继续注册 `disk.smart.read`，保留 `hostScope: configured`、`deviceScope: configured`、现有权限和每日期望间隔。模板与展开语义写入既有双语 `purpose`；没有向严格注册 schema 增加未知字段，没有接受浏览器传入路径、命令、正则或通配符。

## 范围与真实参数来源

- v2 新主机的类别策略默认 `all`：每个已配置目标主机的新鲜库存按原权限/身份和审批约束展开。它不表示全部平台主机，也不授予未来新增盘永久审批。
- `custom` 只选择当前主机下明确选定的 canonical disk ID。空集表示该主机无目标，不回退为 all；未选择的盘不得暗中执行。
- v1 仍使用原有 configured 可信映射，不能显示为已完成 v2 全库存解析；需要独立核验，不自动迁移、补映射或扩大授权。
- 实际设备路径由框架在目标主机库存、host/disk 关系、序列身份及 policy 校验后派生，逐盘白名单编译。当前支持的路径约束是 `/dev/sd` 加 1–3 个小写字母，或 `/dev/nvme` 加 1–4 位数字、`n`、1–4 位数字。此约束只作说明，不接收用户正则作为执行输入。
- all 库存新增/移除/换盘、custom 物理身份改变、端点/pin/路径改变、对象权限或审批撤销均须触发原 guard。不能用同路径、同显示名称或跨主机设备替代已批准对象。
- 当前批次上限 100 个目标，超限整体报错，不静默截断。单盘、全局和后台调度分别管理；`daily-smart/86400` 仍是期望声明，当前后台身份/跨日采集待真实环境测试。

## 全局消费与共享展示合同

插件全局按钮只提交一次 `collectAll({requestId,signal})`，不在浏览器枚举设备或逐盘发 POST。共享服务枚举候选、核对同一授权快照并启动子任务；插件以有界 `collectionAll({operationId,signal})` 读取全部逐盘结果。失败/未知/未执行项不能显示全成功，空集不能当成功。超时不重发命令。

交给框架 operation catalog/registry UI 的最小展示合同如下；这是框架从可信 operation 派生的展示 DTO，**不是本插件新增可执行 manifest 字段**：

```json
{
  "category": "disk",
  "template": "sudo -n -- /usr/sbin/smartctl --json=c --all <disk>",
  "argumentSource": "fresh-host-inventory",
  "expansion": "each-authorized-disk"
}
```

`argumentSource` 表达范式的来源要求；当前计划的 v1/v2 实际可信来源须另列。注册范式、当前解析的 N 条具体计划和已批准范围/计数分别展示，计划和审批仍绑定现有 digest，不因展示字段增加信任。框架负责共享 registry/UI，本插件只在配置页解释自己的声明和范围。

## 验证与待真实环境测试

本地测试使用实际 HTTP/service/policy/broker/history，注入人工 Tower 库存和 SSH 输出。覆盖多主机全盘、SATA/NVMe、两主机相同设备路径的隔离、自选排除、跨主机错误行及非法路径拒绝。合成成功样本不能描述成真实主机健康。

首轮多盘回归复现共享框架失败 `FW-B-Auth-Mid-013`：某主机明确 custom 空集时被计为缺少设备，阻断其他主机已选择盘的整体注册。该失败由框架负责人修正，本插件没有修改共享 broker。框架 0.2.2 本地稳定消费输入下，原四项多盘用例全部通过，完整插件回归 115/115 通过；45 份共享输入在测试前后摘要一致。旧失败日志保留，不把失败改归为缺少真实环境。

修正只认可新鲜 v2 库存解析出的明确 custom 空集；未知、legacy 和缺失库存不能借此放行，也不将空集扩成 all。此结果适用于本次核对的 0.2.2 本地消费输入；正式 final-r2 冻结后的最小回读确认，这 45 份输入与原测试输入一致，因此保留原测试证据而未重复执行。此关联不代表旧框架已修复或真实环境已更新。升级插件包后仍须按框架人工重新审核，不恢复或继承旧审批。

本地配置页需实际核对双语模板可读、说明与逐盘结果分开、渲染不触发请求。实际主机命令、审批和采集只在准确窗口与具体授权动作下执行。VMware 等环境没有有效真实 SMART 样本时标“待真实环境测试”，不伪造结果、不因此自动禁止发布。

0.1.6 与框架 0.2.2 的真实停用态只读 UI 已核对安装版本、磁盘类范式、实际 legacy 来源、预期/已解析 1 与批准 0，以及注册缺少可信映射时禁止授权的提示。展开的单条具体计划与 `<disk>` 范式分别显示，不能描述为全部主机全盘已核验。停用态插件设置正文不可见，未通过启用补测；真实健康、业务采集及每日执行仍待验证。这些边界与已通过的只读 UI 分别记录。
