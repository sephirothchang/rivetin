# 变更记录

## 0.1.6 — 命令范式与逐盘范围展示

- 用途声明与设置页显示 `<disk>` 命令模板、磁盘类别、目标主机库存参数来源要求及 all/custom 边界，区分注册声明与 N 条具体执行计划。
- v2 默认 all 与明确 custom 排除范围分开说明；旧 v1 保留原可信映射，仍需核验，不自动迁移或扩大授权。模板、正则和通配符不作为执行输入。
- 保持操作白名单、权限、host/device scope、物理代际、历史、采集请求及人工审批要求。旧固定包保留，新增多盘及主机隔离消费回归。
- 新增多主机 SATA/NVMe、自选排除、跨主机同路径隔离和非法路径拒绝回归；共享 custom 空主机阻断问题由框架修复，在 0.2.2 稳定消费输入下四项多盘及完整插件 115/115 通过。旧框架不因此视为已修复。
- 无有效 SMART 的真实环境样本和每日执行保持待真实环境测试，本地替身结果不代表实际健康或已部署。

## 0.1.5 — 本地读取提示修复候选，未发布

- 保留后端已有的绑定变化、盘权限撤销、CloudTower 会话失效及插件停用错误，显示准确中英文恢复提示；旧指标/历史清空且立即采集禁用。
- 不从 SMART 读盘失败推断 SSH 认证失败或坏盘，不展示服务端任意异常文本。provider、物理代际、历史和采集请求合同保持不变。
- 增加四类读取失效回归与本地演示场景，新包工厂检查覆盖失效清空；打包拒绝覆盖固定同版包，0.1.3/0.1.4 原包保留。
- 不新增 v2 后端、自动关联或每日执行能力；真实健康样本、后台身份和新组合实机验收仍待验证。

## 0.1.4 — 本地兼容候选，未发布

- compatibility 改为 schema 2：frameworkApi 1、框架版本 `[0.2.0, 0.3.0)`、精确 Tower `4.9.0`、`smtx: "none"`。
- SMTX 产品版本不作为插件的全局准入条件；这不声明任意主机具备 SMART 采集兼容性，也不替代 SSH 目标身份、命令人工审核、返回序列号和样本提交保护。
- 前端 `web/plugin.js` 与原始 0.1.3 包逐字节一致，许可证不变。配置 schema、权限、SSH 声明、历史格式和功能行为均未改变；旧 0.1.3 包原样保留。
- 补充严格 schema 2、版本上下界、API/Tower 不匹配和旧包拒绝的离线验证；服务夹具仍使用非执行 stub，不作为实机采集证据。
- 不包含尚未接通的 device-policy v2，不恢复 SSH 审批或每日计划。新框架／插件组合尚未实机验收，真实有效 SMART 健康样本仍未取得。
