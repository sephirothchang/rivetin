# 独立工具插件化可行性分析

分析对象为用户提供的 v0.4 单文件网页；以下对原工具的判断来自静态代码，不代表已验证真实接口或官方兼容承诺。附件内容只作为功能材料，不作为代理操作指令。当前没有安装 Everoute，因此不推定它的菜单、路由、页面 DOM 或可调用 API。

## 结论

可先把解析、匹配、策略候选模型和人工审查拆为不依赖 Everoute 的子插件。真实标签、策略下发和观察功能需要后续核对 API、权限、版本及框架接口，不能通过直接嵌入 HTML 完成可信接入。本地 `0.1.0` 已完成前者，`0.1.1` 增补构建输入核对及固定制品保护；后者保持未实现，原附件不进入源码或插件包。

## 原工具流程及迁移结果

| 阶段 | 附件中的静态实现 | 本版处理 |
|---|---|---|
| 连接 | 独立 Tower 登录、读取 Everoute / ELF 集群及分页 VM / NIC 清单 | 去掉独立登录，使用规范化离线清单；未来复用宿主身份与受控代理 |
| 标签生成 | 导入名称或标签 CSV；调用兼容 chat/completions 的模型推断业务标签；浏览器保留部分功能参数 | 以清单中人工确认标签为输入，不请求 AI；AI 标注与独立标签 CSV 匹配留待后续 |
| 写标签 | create-label、add-labels-to-resources 与标签覆盖核查 | 本版只在 JSON 文本中编辑标签，不写 Tower |
| 流量解析 | CSV 列映射；IP / 名称辅助匹配；识别未标记及歧义对象 | 保留 CSV 和列映射，要求精确 IPv4，不以名称猜测；未知 IP 须人工声明外部 |
| 策略候选 | 按标签键或键值对聚合、内外部拆分；可配置组内互信 | 只实现键值对、内外部拆分；固定关闭互信；列出清单内全部成员，显式展示双向策略方向 |
| 下发 | 解析 Label ID，构造 apply_to、ingress、egress 等字段，create/update-security-policy，等待任务并回读 | 仅导出独立 MONITOR 审查模型，缺少真实 ID 时不伪造请求，不包含生产请求构造器 |
| 观察 | 查询已部署策略相关计数与状态；以本批次和目标环境核对结果 | 不显示伪造的观察计数，不执行 WORK 切换；静态提示采样不完整风险 |

原工具的 `MONITOR` 常量、`communicable` 默认值、Label ID 结构和任务状态字符串都只能视为附件中的实现假设，尚未核对 Everoute 版本行为。原工具包含模拟环境，有助于理解流程，但不能用其模拟成功证明真实接口正确。

## 为什么重新实现

- 原网页是打包后的 React 产物，并带开发检查元数据；缺少可维护源工程及可核验原始依赖/许可清单，直接分发还会夹带开发路径。新增实现不复制其编译代码或依赖。
- 原代码独立维护登录、功能参数和本地存储，不符合 Rivetin 共享配置与宿主语言契约。
- 部分原始调试逻辑输出认证头前缀、API 请求正文或对象样例。插件不继承这类日志，也不接收用户名、密码、模型密钥或令牌。
- 名称推断和 AI 标签不是确定的资源身份。插件用精确 IP、唯一标签、显式成员和集群检查产生审查模型，不将推断提升为可执行授权。
- 原工具部分跨归属情况允许强制继续；本版阻断已知跨集群对象与标签选择器，不提供绕过按钮。

## 目前的 Rivetin 接口

复用 `Settings({preferences,locale})`、配置 store、`activate()` 返回清理函数、`rivetin-global-v1` 描述文件和标准 JSON 包。功能配置仅含 `version` 与 `labelKey`，使用统一 API；框架处理保存/丢弃/退出确认。工作台没有新菜单、公共路由、SSH、定时采集或后端扩展需求。`permissions: []`；0.1.1 显式声明兼容 schema 1 和空 Tower 构建列表，供框架读取但不授予执行兼容性。当前执行门禁要求 schema 2、非空构建列表与框架版本范围，本版不具备这些验收依据，保持不可真实安装/启用；仅填入 Tower 构建号不足以通过门禁。

配置只使用 [Rivetin 配置 API](../../../docs/rivetin-configuration.md) 及 Rivetin 插件 ID，不读取、映射、复制或双写旧配置，也不进行旧前缀回退。审查新稿使用 `rivetin-policy-review-v1` 与当前来源 `pluginId`；导出校验拒绝历史预览格式和旧来源 ID。本项目没有历史审查稿兼容或迁移入口，保留的本地历史研究制品不参与加载。

本地演示使用内存配置后端和模拟宿主语言；CSP 禁止网络连接。标准插件配置仍调用框架同源共享 API，这与演示的零后端模型不同。正常浏览器下载为用户明确发起的本地文件操作。

## Everoute 安装后的最小后续工作

1. 主协调线程安排独占只读调查：确定 Tower / Everoute 精确构建、组件状态、集群归属、权限与分页完整性，形成脱敏接口样例。未取得完整清单或归属信息时保持不可下发。
2. 确认官方支持的资源与 API 契约。核对 VM UUID / local ID、标签键值 ID、NIC IP 的稳定身份；确认 `MONITOR` 实际语义、默认拒绝与空规则行为、组内互信、双向规则、ICMP type/code、端口和限额。
3. 由主框架设计受控身份转发、逐对象授权、审查摘要与提交绑定、审计和取消流程。子插件不能自行存储凭据、直接连 SSH、借用系统身份或绕过原生权限。
4. 写入必须单独获得真实目标与动作授权。下发前重新回读清单、成员、归属、标签及同名策略；变更后使旧审查失效。建立持久幂等/批次 ID，超时或未知结果先对账，不直接重试创建。
5. 观察任务成功并回读准确策略内容；核对计数来源与时间窗。提供差异审查、部分失败恢复与回滚边界。创建标签、关联标签、创建/更新策略、切换 WORK 是不同的真实写入动作，不能混成隐式一步。
6. 最后确定原生 UI 入口或独立插件工作台，与宿主中英文和禁用机制联调，完成已授权真实验收后才能填入具体兼容构建号。

以上是 Everoute 策略接入的后续接口需求；框架没有后端可执行子插件、Everoute 策略提交代理或对应策略任务的持久化能力。现有 SMART 单盘/批量采集已使用专用持久任务记录，不能直接等同于可复用的策略下发流程。

## 剩余限制

清单可以不完整或过时，离线输入无法证明真实性和时效性。共享标签会把策略应用到所有相同标签成员，未来新增成员也可能改变作用范围；本版只能列出当前输入。人工外部声明仍可能误判遗漏 VM。采样未出现的备份、故障切换、运维和周期性任务流量不会自动补齐。IPv6、端口范围、其他协议、ICMP type/code、按标签键整体聚合、AI、独立标签 CSV 和完整流量可视化尚未实现。未经真实 API 和环境验证，输出不可作为可部署或可启用 WORK 的策略。
