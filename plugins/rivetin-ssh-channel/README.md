# SSH 通道

`rivetin-ssh-channel` 提供统一 SSH 采集通道的配置入口。框架负责连接、命令策略、审核授权、执行计划和日志；子插件不自行取得主机密码或提交任意 shell 脚本。

## 默认状态与授权边界

- 框架默认附带本插件，安装状态与默认安装迁移由框架处理。插件生命周期开关、插件配置中的“允许通道执行采集”均默认关闭，安装本身不会建立连接。
- 只有框架、SSH 通道生命周期、通道配置均启用，且消费插件已通过审核，才允许在批准范围内执行。管理页在通道关闭时仍可供只读审计。
- 消费插件的 SSH 能力安装后默认未授权。审核页列出命令、操作类型、目的、目标主机和设备、执行计划与摘要；管理员先审阅，再勾选确认并二次提交。授权状态必须从服务器回读确认。
- 命令、版本、目标或计划变更后，既有授权失效。关闭、重置或更改通道配置也需重新审核，不能仅重新打开开关便恢复旧授权。
- 只接受框架允许的结构化只读操作。未知操作、任意 shell、远程下载执行、删除、格式化、重启和网络修改等注册会被拒绝。页面保留不可执行的高危示例及风险说明，不以有限关键词黑名单代替允许列表。

命令预览、摘要、挑战和有效期都以服务端审核结果为准。前端的按钮禁用与二次确认用于明确管理员意图，不能替代服务端权限验证，也不构成插件代码沙箱。

命令页按消费插件与设备类别展示范式和具体计划。`<disk>` 是范式参数；“参数来源要求”说明需要什么证据，“当前解析来源”说明实际用了什么。旧设备映射不代表已核验当前库存；预期、已解析及已批准目标的数量分别显示。展开计划只供查看，不会审核、授权或执行命令。

## 配置与主机凭据

通道配置复用统一 `/api/rivetin/v1/config`，按本插件 ID 独立保存，编辑使用草稿与明确保存。默认配置为 `{ version: 1, enabled: false }`，只包含版本与启用偏好，不包含密码、私钥、命令或主机清单。升级保留既有配置；配置中的启用偏好与插件生命周期开关分别生效，兼容声明通过不会自动启用通道或授予命令权限。

SSH 功能页提供独立连接草稿：整组凭据优先级为主机 > 集群 > 全局，不跨层拼接账户和密码/私钥。配套框架的 connections v2 编辑器可从当前 CloudTower 只读清单批量选择主机；已有管理员映射别名保留高级编辑入口。每个新主机继承凭据，指纹留空，仍须明确核验 IP、端口和 host key；不会因全局凭据而自动连接主机。改选不同主机时，旧指纹和设备选择失效，须重新核验。

v2 设备范围按磁盘、GPU、USB、PCIe 分别选择全部或自定义；新目标默认全部，自定义空集表示不允许该类设备。自定义磁盘通过服务端 fresh 清单选择规范 ID，路径、序列号与代际由服务端解析，客户端不填写或持久化这些原始身份。既有自定义范围不会自动放宽，清单过期、跨主机或身份变化需刷新重选。GPU、USB、PCIe 尚无执行能力；保存范围不授权命令，也不代表已支持这些设备。实际清单、迁移及执行门禁须由配套框架完成联调。

表单使用插件中心既有保存与未保存退出流程，不自动保存。密码和私钥只接受明确的保留、替换或清除；默认空表单保留已有秘密，替换操作必须提供新值。清除较高层凭据会使该层不可用，不会偷偷回退使用较低层秘密。后端使用独立 AES-256-GCM 凭据库，GET 仅返回 `hasPassword` / `hasPrivateKey` 等摘要，不返回已保存秘密。新输入仅存在草稿内存和受认证的 PUT 请求中，不进入普通配置、localStorage 或日志。保存连接设置前撤销全部 SSH 审批并中止在途连接，再原子保存；不会因保存而连接主机。

配套框架的 connections v2 编辑器使用 revision 检查和保存回执。版本冲突保留草稿及原保存基线，不自动覆盖服务器的新配置；保存结果未知时保留草稿、暂停编辑及重复提交，可点击“核对保存结果”只读确认原提交。确认前不会再次提交，也不会把历史回执中的旧摘要当作最新配置。旧连接格式仅显示只读投影，必须通过配套工具显式迁移，网页不会自动转换或放宽原有设备范围。上述编辑器随框架提供，固定 0.1.1/0.1.2 子插件包不因此重建。

也可通过便携 CLI 的 `channel import-host --host-profile-file <sensitive-file>` 导入受控敏感文件，不在命令行参数中携带秘密；底层数据 CLI 使用标准输入。首次 Web 保存保留现有 CLI 主机为明确的主机例外；后续 CLI 与 Web 使用同一连接存储。具体 API 与边界见 [SSH 通道契约](../../docs/ssh-channel.md)，本插件包不提供服务端执行脚本。

凭据库密钥丢失且已有主机密文时，导入会以 `SSH_VAULT_KEY_MISSING` 失败，保留原密文且不生成替代密钥。应从受控备份恢复原密钥，再验证既有资料可解密；不能通过反复导入恢复丢失的密钥。

采集失败记录保留消费插件、命令、主机、设备及采样起止时间和固定错误码，不保存失败输出或 stderr。最近结果受每插件 30 条及总字节上限约束，不能作为逐盘每日长期历史；Tower 资源映射、资源读取权限与独立持久历史仍需共享 provider 实现。

框架的 SSH 审计组件使用 `GET /api/rivetin/v1/ssh-channel` 读取状态，使用同一路径 POST 的 `review`、`approve`、`revoke` 操作处理审核。它不从浏览器连接主机，不提供交互终端，也不在 localStorage 保存审批或功能配置。

## 本地开发

复用框架锁定的 React、webpack 和 jsdom，无新增插件依赖：

```powershell
npm test
npm run build
npm run package
npm run verify:package
npm run demo
```

演示：[回环地址上的本地模拟](http://127.0.0.1:43184/)。演示中的主机地址是文档保留地址，凭据状态、注册和审批均为内存模拟，HTTP CSP 明确禁止网络连接，不连接 CloudTower 或真实主机。可以验证默认关闭、审核/取消、勾选后二次确认、授权失败、撤销授权、中英文和高危示例；浏览器刷新后恢复默认。

标准插件包为 `release/rivetin-ssh-channel-0.1.2.rivetin.json`，仅包含前端设置和 LICENSE，安装过程不会向主机执行命令。0.1.2 只更新版本和结构化兼容声明：要求框架版本 `>=0.2.0 <0.3.0`、框架 API 1、CloudTower 构建 `4.9.0`；不声明 SMTX 产品版本依赖，也不代表已验证所有主机或设备。旧 0.1.1 包保持不变，不能覆盖其内容。

连接编辑器和加密后端由对应框架构建提供；只升级子插件包不会更新框架后端，也不会迁移连接文档或新增设备操作。分类设备范围及批量目标须由配套框架分别完成接口、迁移和执行门禁联调，不能以此兼容声明代替能力验收。真实主机兼容性须分别验证，不能以本地演示代替真实采集验收。

0.1.2 已在框架 0.2.2 下完成停用状态的真实只读界面检查：版本与兼容提示、旧连接只读与显式迁移提示、命令分组及范式/实际来源、未授权门禁。该检查没有启用通道、修改配置、迁移连接、审核命令或执行采集；启用后的主机连接、命令执行及采集仍待真实环境测试。历史失败记录不会因本次界面检查通过而改为成功。
