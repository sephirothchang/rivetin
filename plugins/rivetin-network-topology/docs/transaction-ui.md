# 真实网络事务的客户端交互设计

状态：2026-10-29，本轮开发设计，尚未冻结事务 HTTP/SDK 字段。依据[框架事务设计初版](../../../docs/network-transactions.md)；该文档记录的是官方能力研究与设计，不能解读为真实操作已可用。页面使用[通用 UI contributions v1](../../../docs/plugin-ui-contributions.md)，资源提供器沿用[只读合同](../../../docs/plugin-workpages.md)。

## 草稿与可执行能力

布局、关联草稿、服务端计划、正在执行的事务分开呈现。实际拓扑实线保持资源快照；关联意图用虚线和差异列表，不把拖动结果标“已生效”。每项显示对象 ID、原/目标 VDS，NIC 还显示原主机，服务器计划则必须展示完整受影响资源和正/反向集合，不只显示一个网口。

框架研究初版记录：4.9 的 update-vds 接收完整 nicIds 集合并返回异步任务；update-vm-vlan 没有保持身份迁移到另一 VDS 的字段；update-nic 也不是归属迁移接口。这些研究结果只约束本插件的候选动作，不能变成前端直接拼原生写请求的依据。

| 本地意图 | 页面当前呈现 | 后续真实计划的条件 |
| --- | --- | --- |
| VDS/网络布局移动 | 仅页面位置，不进入网络事务 | 不调用网络写接口 |
| 虚拟网络换属 | 保留本地意图和差异，显示“真实迁移未开放” | 有正式、保持资源身份的支持证据和服务端能力；不删建替代 |
| NIC 从已知业务/迁移 VDS 调整归属 | 保留本地意图，显示真实变更能力尚不可用 | 服务端核对完整原/目标集合、原生任务、第三方并发和可逆性，并提供独立回滚身份及进程外到期保护 |
| NIC 原用途/归属未知，或管理/存储/混合保护对象 | 拒绝生成相关草稿，解释缺少的用途/身份/完整性依据 | 不通过名称、局部清单、只读权限或编辑按钮放行 |

真实动作由服务器能力决定。缺少独立回滚身份或进程外到期保护时，应用必须不可用；不能只凭前端已选网口、接口字段存在或 inventory.read 权限放行。能力未知、读取失败与明确不支持分别显示。混合意图中含不支持项时，整份计划不可应用；允许用户显式撤下该意图后重新预检，不能静默过滤并应用其余部分。

## 阶段呈现和允许的用户动作

以下名称沿用框架设计初版的概念状态，最终以权威响应字段为准。用户动作必须同时满足服务器返回的能力、准确事务身份、预检及期限要求；表中动作不是单凭状态即可开放的本地允许列表。

| 概念阶段 | 呈现重点 | 用户动作及限制 |
| --- | --- | --- |
| 本地草稿 | 差异、保护原因、未应用 | 修改/丢弃/请求服务端预检；能力未交付时只保留本地审查 |
| planned | 服务端计划、完整对象集合、风险、计划期限和已核回滚条件 | 明确风险确认后才可请求应用；修改草稿使旧计划失效，不能套用原证明 |
| preparing / applying | 原操作 ID、原生任务、服务器截止时间；90 秒已包含应用过程 | 禁止再次应用；仅重新读取或停止页面等待，不能把 HTTP 成功标成已应用 |
| awaiting-confirmation | 正向任务和准确 postimage 已由服务器核对、剩余服务器期限 | 仅在服务器允许时确认保留或请求回滚；本地时间不能延长窗口 |
| rollback-requested / rolling-back | 撤销请求与反向任务进度 | 等待原事务状态；请求接受不等于恢复完成，不再发起另一事务 |
| confirmed | 服务器持久确认终态及最终观察 | 读取新资源快照；不由前端删除事务记录或假造新基线 |
| rolled-back | 反向任务完成且 preimage 已回读 | 读取恢复结果；不从前端计时结束推断此终态 |
| rejected | 服务端拒绝原因，未应用证据 | 保留本地意图供修正；新计划仍需完整预检 |
| apply-unknown / rollback-unknown | 原事务身份、最后已证实状态和不确定阶段 | 只读原事务并提示可能需要人工处理，不重发旧动作、不换 ID 绕过锁 |
| conflict / manual-intervention | 冲突对象、未完成项及人工处置提示 | 禁止前端覆盖第三方状态或自动重放，保全证据并联系管理员 |

## 时限、断线和恢复

- 显示服务器的真实截止与观察时间。前端倒计时到零显示“已到截止时间，正在核对服务端结果”，不得自己设置 rolled-back 或发送唯一回滚请求；时间异常/观察过旧时重新读取，不推算出新的完整 90 秒。
- 应用响应丢失保留原计划/事务身份并读取原事务；不能自动再次 apply、分配另一身份或让用户以另一草稿绕过未知锁。确认/回滚响应未知同样先调和。
- 退出页面、AbortSignal、停止等待只清理客户端请求和监听，不取消已提交事务，不自动确认/回滚，也不删除服务端 journal。
- 重新进入需从服务器发现当前操作者/集群的原事务并恢复状态，不依赖 localStorage、普通配置 PUT、浏览器内 timer 或遗失的 operationId。发现结果必须与准确集群、操作者、计划和事务身份对应，不能用“最新一条”代替唯一关系。
- 本地未提交草稿与已提交事务分栏处理。`onDirtyChange` 仍表示本地草稿；已提交事务不能称为可“丢弃”的编辑。最终离开/恢复交互须与框架合同对齐，不能让“丢弃并退出”暗示服务器撤销成功。
- 读取有取消、超时、退避和总等待上限。停止等待后保留最后已核状态和原事务 ID，允许显式重新读取，不自动重复业务动作。

## 客户端专项验收清单

正式合同交付后，使用明确 fake provider 验证下列行为；这些测试不能写成真实服务端回滚已通过：

1. 不支持网络换属、独立身份/到期机制缺失、未知用途、过期/不完整预检和混合不支持意图时均不能应用。
2. 计划变化、身份/集群不匹配、迟到响应及旧计划证明不能触发新事务；快照 hash 不当 CAS。
3. apply/confirm/rollback 的 HTTP 接受与业务终态分开；unknown 只回读原 ID，不出现重复写调用。
4. 应用过程也占确认窗口，到零、时钟偏移和页面后台暂停均不产生前端伪回滚。
5. 取消等待、路由切换、停用和卸载不取消/确认/回滚服务器事务；重新进入读取原持久事务。
6. 反向任务失败、第三方冲突、journal 不可用、服务器返回 manual-intervention 分别展示并锁住真实动作，不静默重置为成功或新草稿。

精确 capabilities/plan/apply/confirm/rollback/status 路径、请求和响应、权限及实际最低版本由 FW 给出权威合同后消费；当前没有增加猜测的方法、HTTP 请求或模拟成功状态。
