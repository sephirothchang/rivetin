# 实装接入方案（已接 UI 合同，真实只读有限实测）

用户要求实装网络拓扑可视化编辑插件，并已明确本轮同时开发真实网络变更与服务端回滚。页面阶段先接入真实只读清单和工作页：布局仅影响页面位置，网络关联和 NIC 归属形成明确标记的内存草稿与差异审查。随后紧接服务端真实事务消费；页面先验收不能作为整项结项。当前服务端事务能力尚未交付，页面明确显示不可用，不发送真实修改请求。独立 Demo 的合成数据和 90 秒模拟不进入工作页。

框架 0.2.6 与本插件 0.1.3 / C03 在目标产品构建 4.9.0、当前中文下已验证：原生拓扑工具栏入口、右侧工作区及原生树/标题/页签保留、准确当前集群的只读资源关系展示、父子节点最小页面布局移动、干净返回原生画布、重入后布局复位。资源观察时间与版本在布局操作中保持，重入发生新的读取。这不证明底层 DTO 的所有字段、分页或完整兼容矩阵均已验收；本次未额外捕获原始提供器响应。

用途来源仍有疑点：带管理/存储原生标识的对象显示为 workload，尚未核实可信枚举和映射，暂不确认为 Bug，也不宣称实机保护已通过。未生成本地关联意图，真实草稿及 dirty Cancel/Discard 仍待可信条件后验证。未通过名称推断用途、放宽保护或创建对象补测试条件。

本次未切语，034 仅本地修复和本地动态验证，真实切语待测试；不修改账户/全局语言、浏览器偏好或 viewport。本次记录 45 条共享模块版本 warning、2 条初始化 HTTP 504 error；504 堆栈位于原生 bundle，但端点、根因及是否与插件相关尚未证实。有限功能可用不能替代这些未决项。

真实网络事务及独立回滚仍未实现，为本轮后续；本次未执行共享配置保存、真实网络应用/确认/回滚、SSH 或身份创建。原 C03 包与运行代码、历史固定候选和报告不变。本节只补后验文档，原始环境值、资源标识、图/DOM/logs和窗口记录仅存本地，不进入公开资料。安装保护与正式闭窗按各自负责人独立回执记录，不由本页 UI 结果推定。

## 归属和共享依赖

- 插件实现自己的内部视图模型、校验、四列画布、详情、本地草稿及生命周期；不读取凭据、不抓取 Tower DOM、不自行调用原生 GraphQL/HTTP 或主机接口。
- 用户选定入口为现有集群“网络拓扑”页的“可视化编辑”按钮，不增加 Everoute 独立导航。插件通过 `ui.contributions` 声明按钮及页面目标，框架统一负责语义插槽、登记卸载、页面承载与离开守卫。入口合同为[通用 UI contributions v1](../../../docs/plugin-ui-contributions.md)，资源读取合同为[只读提供器](../../../docs/plugin-workpages.md)。
- 框架提供认证及插件归属范围内的只读资源提供器。最低需求是列出允许查看的集群，并按准确集群返回拓扑快照。读取支持 AbortSignal、上限和超时；插件不得接收 token、Cookie、原生认证头或主机连接能力。

源码使用 `ui.schemaVersion:1`，`pages` 声明 `topology-editor`，`actions` 为空；`contributions` 声明 `open-topology-editor`，目标为该 page，slot 为 `cluster-network-topology.toolbar.actions`，双语 label 为可视化编辑/Visual editor，icon 为 edit、order 为 100、visibility 要求 clusterId。不再返回旧 `workPage`，不双注册；manifest 不新增 UI 字段或权限。组件接受 `active,locale,signal,onDirtyChange(boolean),context`；仅 active 严格为 true 且未取消时启动。`context` 为框架生成的 `{schemaVersion:1,section,clusterId}`，首读必须使用该 clusterId；缺失或不在完整允许清单内时失败关闭，不能默认第一集群。内部集群选择锁定跟随原页面，context 变化重新挂载、取消旧请求并隔离迟到结果。插件内部 ref/effect 管理自身 DOM；语言变化只调用同一控制器的文案更新，保留草稿/布局/读取，不因 locale 销毁重建。active、signal 或集群上下文变化才执行清理。框架不提供 raw root 或认证材料。脏草稿交框架提供取消/丢弃退出，不保存为普通配置。

provider 为 `options.networkTopology.provider.listClusters({signal})` 与 `read({clusterId,signal})`，适配层 `provider-adapter.js` 校验并解开 `{schemaVersion:1,source:'cloudtower',observedAt,complete:true,clusters}` 信封，再送入内部模型。框架采用既有 `inventory.read`，服务端硬绑定本插件 ID、active 状态、最低框架版本及 Tower 管理员。源码最低框架版本为 0.2.6，目标 Tower 产品版本为 4.9.0；这些声明与上述有限实测不代表全部真实集成或保护测试均已通过。市场载体保留 deprecated max 0.3.0 以支持旧 reader 语法，新框架不执行上限，原固定包/ML0不改。

## 资源 DTO 需求与内部视图模型

以下为沿用只读提供器合同消费的规范化 DTO，由插件适配层校验；HTTP/SDK 的权威定义以上述共享文档为准。

快照需要 `schemaVersion: 1`、`source: "cloudtower"`、`cluster: {id,name}`、SHA-256 `revision`、带时区的 `observedAt`、`complete`，以及下列数组。`observedAt` 是资源实际观察时间，不能用页面刷新时间伪装；`revision` 不冒充服务器并发写令牌。

| 内部字段 | 最小内容 | 未知与可信条件 |
| --- | --- | --- |
| `hosts` | `id,name` | 不需要主机管理地址或凭据 |
| `switches` | `id,name,mtu,purpose,networks[]` | purpose 需可信分类；不能由名称猜测用途 |
| `networks` | `id,name,vlan,purpose` | 全局唯一 ID；VLAN/用途未知用 null |
| `nics` | `id,name,hostId,switchId,link,speedMbps,bond,bondMode,peerId,peerPort` | 无 VDS/邻居用 null；链路允许 unknown；不猜测 A/B、active/backup 或 VLAN 覆盖 |
| `vmGroups` | `networkId,count` | 仅真实、去重的关联计数；缺失不能补成零 |
| `peers` | `id,name` | 仅已有 LLDP 邻居；无证据展示未知，不创建模拟交换机 |

跨页读取必须由框架以有界分页汇总并核对集群身份、去重、引用完整性和结果上限。分页未结束、接口缺失或来源无法证明时，不能把部分结果标 `complete:true`。查询出错不得退回 Demo。内部上限为 200 集群、128 主机、128 VDS、512 虚拟网络、1024 NIC、512 VM 计数组和 256 LLDP 邻居；超限拒绝展示。本插件不直接调用服务端路由；由注入 provider 实现读取，身份/配置/网络资料不进入制品。字段采样只证明真实资源形状，不证明本插件已安装或权限集成通过。

## 页面内草稿边界

只有完整、新鲜快照中用途为 workload/migration、且其全部网络用途也可信的 VDS，才能作为关联草稿的来源或目标；管理、存储、用途未知和混合保护对象拒绝编辑。观察超过 60 秒时停止新增草稿，并提示重新读取。草稿不修改快照、共享配置或服务器对象，不代表网络预检已完成。

NIC 的原 VDS 必须同样具有可信可编辑用途；`switchId:null` 不能单独证明它没有参与未知网络，本阶段只读展示，拒绝生成该 NIC 的绑定草稿，不通过完整分页状态推断未关联端口的安全用途。

差异必须显示对象身份、原/目标 VDS，NIC 还显示所属主机。真实上联连通性、MTU/VLAN 覆盖、虚拟机依赖、权限、服务端 CAS、事务幂等、执行审计、90 秒独立服务回滚和部分失败恢复，均是后续真实应用合同。没有这些证据时只允许本地审查，不提供“应用”操作。布局、草稿和真实资源分别展示，未保存离开及丢弃行为在共享工作页合同中统一接入。

## 本轮真实事务消费需求（待框架权威合同）

以下是客户端需求，不是已经存在的请求字段或服务端能力。FW 先基于准确产品版本核对原生写 API、可逆动作和独立回滚身份，负责 journal/preimage、原生任务、并发校验及服务重启后的 unknown 恢复；插件不实现或转发原生写 API。

- 能力显示必须按服务端实际支持、准确对象/用途和可逆性决定，未提供/不支持/未知时禁用真实动作，不由前端推断可用。
- plan 必须由服务端重新校验身份、权限、依赖、完整性和并发，返回可审查差异、风险及后续所需的真实预检证明；资源 snapshot 的 revision 只是 hash，不作为写入 CAS。
- apply/confirm/rollback 必须绑定准确计划/事务和幂等身份；未知响应先查原事务，不盲目重发、重新分配或自动重复 apply。计划阶段不等于已应用，回滚请求接受不等于回滚终态成功。
- status 应支持已知事务及重连后的当前事务发现，避免刷新后仅依赖遗失的页面内 operation ID。状态、原生任务和审计来自服务端 journal，不把客户端布尔值或普通配置 PUT 当事务记录。
- 服务端持有截止时间并独立执行回滚。前端显示倒计时只用于提示，到零后仍等待服务器回读；不得自动把页面内到期写成回滚成功，也不靠浏览器定时器触发唯一回滚。
- 取消页面等待或 AbortSignal 只停止本页请求/轮询，不取消已提交的真实事务；离开后服务端继续执行，回到页面读取同一事务。轮询有上限、退避和超时，停止等待后允许显式重新读取，不重复业务动作。
- `onDirtyChange` 表达未提交的内存草稿。已经被服务端接受的事务不能称作“丢弃草稿”，更不能在卸载清理时发起取消/回滚；其离开提示和恢复语义须与框架共同确认。

尚未写出无依据的事务方法/响应模型或模拟成功入口。收到最小正式合同后，实现真实计划审查、apply/confirm/rollback/status UI、unknown/超时及恢复专项，再按固定方案安排实际执行验收。当前授权仅覆盖开发与本地客户端测试，未开放任何真实网络写或回滚调用。

已按[框架事务研究初版](../../../docs/network-transactions.md)整理[客户端事务交互设计](transaction-ui.md)：虚拟网络换属保留为本地意图，但当前缺少保持身份的真实迁移能力，不以删建替代；NIC 真实变更须由服务器完整集合预检和可逆性/独立回滚能力决定。该设计不是已冻结的请求或已实现事务状态。

## 版本、制品和验收

旧 0.1.0/C04 与所有历史固定包保留。新安装候选使用独立版本/目录，不能重打同名固定包。无 max schema2 声明的读取 floor 至少为 0.2.4；若新工作页需要更高框架版本，必须提升实际最低版本。当前生产市场仍服务旧 reader，发行字段策略由协调后的统一合同决定，不自行混入使旧 reader 拒绝整份清单的新声明。

本地注入数据、jsdom 或浏览器 fixture 只证明插件交互，不证明 CloudTower 字段适配、权限或真实部署。页面验收依次需要本地专项/渲染、共享 DTO 集成、独立固定包、主协调准确安装窗口、真实资源只读回读及内置浏览器检查；本轮真实事务继续按正式合同实现。实际网络写入与回滚执行须由主协调按固定方案列明精确 API/对象、备份、影响、停止条件和验收目标后安排独立窗口。
