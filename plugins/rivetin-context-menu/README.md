# Rivetin 对象右键菜单

`rivetin-context-menu` 为 CloudTower 提供侧向多级右键菜单。**菜单仅作入口，配置、权限判断、确认与任务执行复用官方原生界面。** 不增加资源写入 API、不复制官方 handler、不读取 React 私有状态或认证材料。

当前固定版本为 **0.5.9**，修复 A→B→A 后宿主复用退休侧栏导致原生入口无法恢复的问题。仅在已核验的 VM 列表与准确源行上，先移除只读 sidebar 路由，等待旧面板真正卸载，再选择原准确行并核验全新面板；旧节点不会恢复资格。准确的原生 reset 边只接受一次，外部排队导航证据仍使操作失效，不能仅凭当前 URL 等于 reset 继续。无法重建时显示插件自己的可关闭诊断。本次定向真实验证范围见下文，完整功能变更见 [CHANGELOG](CHANGELOG.md)。

## 本次真实验证范围（2026-10-29）

在 CloudTower 4.9.0、Rivetin 框架 0.2.2 的开发测试环境，使用同一固定 0.5.9 包完成了以下实际内置浏览器检查，随后保护后验通过并关闭执行窗口：

| 已验证项目 | 实际范围 |
| --- | --- |
| 全局列表首次菜单 | 新文档、无预开侧栏，从 `#/vms/` 的资源行首次右键显示准确对象菜单 |
| 原 A→B→A 故障路径 | A 的官方 CPU 编辑器首开、读取初值并取消；B 只读身份导航且不开编辑器；返回 A 后再次打开准确 A 的新官方编辑器，核对标题、对象及初值后取消 |
| 其他安全入口 | A 的内存、磁盘、NIC 官方编辑器仅读初值并取消；不修改字段、不提交业务 |
| 菜单交互 | 侧向级联、键盘与 Esc 分层关闭、Shift 右键不触发插件菜单，以及当前 1280×720 桌面视口边界 |

`CTX-B-Life-Mid-020` 仅在上述定向范围内验证修复并关闭。真实外部排队事件注入、业务保存和任务完成、其他语言／视口、独立生命周期切换及主机全矩阵均未据此验收；排队事件取消仍只有源码、精确生产 bundle 和本地浏览器证据。现场记录了 45 条宿主共享模块警告、0 条控制台 error；官方审计镜像权限拒绝保留，未记为成功。

固定包为 166781 字节，SHA-256 `bd33fce9ab2c664f8612cb873b4391fb53038c09cfd8bcfb40f9de141556f8ee`。包内说明保留冻结时点的状态，本节补充其后真实验证结果；未为更新验证文档重新打包。发布与下载状态以正式清单为准。

0.5.8 已冻结为未部署的本地候选，独立审查发现其 reset 当前 URL 豁免可能吞掉排队的外部导航事件；补充源码和精确 bundle 复现后，该候选不通过，原包与日志保留。0.5.9 使用独立新包修正守卫，未复用 0.5.8 的测试通过作为新输入结论。

0.5.7 在框架 0.2.2 的真实新文档中通过了全局列表首次右键、级联键盘及 CPU／磁盘／NIC／HA 官方编辑器打开取消；A→B→A 返回后的 CPU 入口没有打开，因此该版整体实机验收失败。0.5.6 的历史尾斜杠首次菜单失败、0.5.5 独审遗漏与 0.5.3 旧风险证据继续保留，不能用局部或本地通过覆盖实际失败。

0.5.6 曾完成本地固定包、独立源码与精确 bundle 复核：源码全量 781 项、编译后 factory 21 个场景及 NIC 菜单/配置轮询回归通过，同页面第二次执行插件 bundle 的退休隔离也已覆盖。本地模拟验收通过仍未覆盖真实全局列表的尾斜杠路由，因此不能替代实机结果。宿主复用已退休 DOM 时仍安全拒绝；本地演示中观察到这种拒绝，新 document 可恢复正常入口，真实环境的错拒范围仍待验证。0.5.7 必须使用新固定包重新验收，不继承旧版放行结论。

## feat: 资源列表菜单

新增以下列表的官方操作菜单接入：

| 页面 | 菜单来源 |
| --- | --- |
| 主机、物理盘、网口 | 被右键行自己的官方 More 菜单 |
| 虚拟机组、虚拟机放置组 | 被右键组自己的官方菜单 |
| 虚拟卷 | 精确卷 ID 对应的官方菜单 |
| 虚拟机网络、系统网络、虚拟分布式交换机 | 被右键网络或交换机的官方菜单 |
| 虚拟机快照、快照计划 | 快照或计划自己的 ID 对应菜单；不以 VM ID 代替快照 ID |

插件读取官方实际提供的菜单标签、禁用状态与层级，呈现为侧向级联菜单。准备阶段只展开和关闭自身定位的 More／子菜单，不选择业务叶子；用户选择操作后重新打开并核验同一对象的原生路径，然后点击一次该官方入口。对象、路由、菜单含义或状态变化时停止，不根据同名文字猜对象。

菜单可用性跟随官方状态、权限、硬件及许可。官方当前没有提供的项目不会被插件虚构为可执行能力；也不保留“尚未适配”的固定占位。菜单交接不等于业务操作成功。破坏性操作仍使用官方确认界面，插件不会继续点确认或修改字段。

## feat: 虚拟机快捷入口

右键列表 VM，无需预先打开侧栏，即可选择以下原生入口：

| 类别 | 接入方式 |
| --- | --- |
| 基本信息、CPU、内存 | 官方编辑虚拟机对话框 |
| 磁盘、缓存、CD-ROM | 官方磁盘编辑器；不自动选择或改动具体设备 |
| 网卡、QoS | 官方网络设备编辑器 |
| 高可用、放置组、随主机开机、所属用户 | 对应官方配置对话框 |
| 主机名、DNS、NTP、账户密码 | 对应官方客户机配置或操作入口 |
| 控制台、关机、重启、暂停、克隆 | 已核对的官方工具栏入口；不认领任务完成或控制台连接成功 |
| 迁移与跨集群迁移 | 官方迁移向导，不预选目标 |
| 快照 | 官方快照页与创建入口；恢复、重建、删除在精确快照行菜单中选择 |
| 组、模板、隔离、网络链路、流量、工具映像、回收 | 官方对应菜单或操作入口 |
| 监控、网络安全、备份与容灾、事件、标签 | 原生页签导航；不等同于备份或配置任务执行 |

完整编辑和 More 菜单也保留入口，跟随当前官方界面显示其他可用功能。强制重启与普通重启等语义不同的动作不会互相冒充。控制台需要浏览器仍有用户激活状态；过期时安全拒绝，不预开空白窗口或拼接控制台地址。

## 交互和配置

主菜单保留，悬停或点击分组向侧边展开；支持屏幕边缘避让、多层键盘导航、独立滚动、Esc 逐层返回与完整清理。支持 manual popover 的浏览器使用顶层绘制，DOM 仍留在宿主事件边界。Shift + 右键保留浏览器菜单。

资源类型设置扩展为15种，保存仍使用框架独立配置与草稿机制。已有version1配置保留原勾选，不自动扩大用户设置；升级后在插件设置中勾选新增资源类型并保存，或明确重置到新版默认值。框架与其他插件配置不受影响。

## 验证与兼容边界

旧面板／控件一旦跨对象导航失去归属证明，即使补上同名标题或对象 ID，也不会重新用于点击。该隔离在同一页面的提供器重建、停用再启用和多实例之间保留。首次启用时已有侧栏若没有精确公开对象 ID，同样不能仅凭路由和名称认领；界面会提示重新打开对象详情。真正重新创建且通过身份核验的官方面板仍可使用。

退休隔离同样覆盖外部列表的 More 控件、原生弹层和菜单项祖先；VM 入口与非 VM 行适配器消费同一份 DOM 身份状态。状态由插件自己的 document 标识保存，同一页面重新加载插件脚本也不会洗去退休记录；换新标题、移动叶子或重建适配器不能恢复旧回调资格。正常的同对象隐藏菜单重新展开保留原生生命周期；只有实际失去归属的节点被退休。公开禁用 class 与原生 disabled/ARIA 状态均在点击、页签选择及清理前检查。

侧栏重建只接受已知全局 VM 列表，或数据中心／集群／主机的 `view="vms"` 列表及唯一准确 sidebar 参数；未知路径、重复参数和操作形查询不触发重建。源行变化、旧面板未卸载、旧控件被移动进新面板或外部导航介入时仍停止。提示最长保留 30 秒，可手动关闭，停用时清理；不修改宿主面板字段或提交业务。

0.5.9 固定包使用兼容性 schema 2、框架 API 1，原始元数据保留最低框架版本 `0.2.0` 和旧最高版本字段 `frameworkMaxVersionExclusive: "0.3.0"`。这是该包发布时的声明，包内容与摘要保持不变。框架 0.2.3 及旧解析器仍按旧字段规则检查 `>=0.2.0` 且 `<0.3.0`。

自框架 0.2.4 起，仅检查包含最低边界的 `frameworkMinVersion`；旧最高版本字段只为旧解析器保留格式，不再参与版本准入，也不在兼容性详情中显示上限。该版本行为说明不新增本插件的实机验收范围，具体见上文真实验证记录及下方权威兼容性文档。框架 API 1、CloudTower 构建 `4.9.0` 及独立 SMTX 条件保持不变；`smtx: "none"` 表示不直接调用 SMTX 服务或解析其协议，原生操作可用性、权限、确认和任务执行仍由 CloudTower 判断。

新省略最高版本字段的 schema 2 声明必须将最低框架版本设为 `0.2.4` 或更高。仍服务 0.2.2／0.2.3 的生产 V4 市场清单继续保留旧字段，因为加入一条无该字段的记录就可能使旧框架拒读整份清单；当前包无需为此改写或重新打包。完整规则见[兼容性声明与读取版本](../../docs/rivetin-compatibility.md#旧字段与读取版本)。


适配目标为 CloudTower 4.9.0 的公开 DOM。列表类型使用已核对的路由、同表完整表头组合及精确行 ID；未知结构、多种匹配、未知弹窗、源节点重用或禁用控件均拒绝接线，不降级为全局文字搜索。英文插件文案与标签在本地测试，官方英文环境尚未实机验证。

本地 demo 的宿主原生窗口也是明确标识的模拟，不连接真实环境。真实验收须与主协调聊天安排独占窗口，并区分菜单展示、对话框打开与取消、实际业务提交；不能用本地模拟声称实机操作成功。

## 已停止的旧路线

`0.3.0` 的自建表单、请求构造器和独立资源后端属于未部署、未采用的研究候选。原始制品和证据保留，以便审查和追溯；其测试通过不表示仍会接入生产。生产入口已不引用这些模块，不能把它们作为原生入口缺失时的后备写入方案。

本地旧研究只可通过显式 `forms=legacy-0.3` 访问，并有明显标识；`forms=production` 不再启用旧业务表单。普通 demo 模拟宿主官方界面，不连接真实 CloudTower。所有配置仍复用 Rivetin 的独立配置及草稿保存机制，详见[配置契约](../../docs/rivetin-configuration.md)。

## 开发

使用现有 Node.js 22、框架锁定的 webpack、React 和 jsdom，不增加依赖。在插件目录运行：

```powershell
npm test
npm run build
npm run package
npm run demo
```

打包输出路径为 `release/rivetin-context-menu-0.5.9.rivetin.json`；路径说明不代表已有验收通过的固定包。构建和打包不代表上传、发布或部署；真实原生入口验收必须与主协调聊天安排排他窗口。

本地演示仅监听 [127.0.0.1:43180](http://127.0.0.1:43180)。具体原生桥协议见[入口提供器说明](docs/action-provider.md)。

## 历史验收记录

旧品牌 `0.2.2` 的受控预发布验收仅通过了列表原生菜单路径，内部虚拟磁盘展开却使宿主侧边栏关闭，因此未通过。该验收结束时已禁用子插件并保留配置；这不表示用户此后的手工状态。旧包、原始截图和备份保留于本地忽略目录，不进入新包。新源码已增加宿主 outside-click/Escape 边界回归，本地修复不能冒充真实复验通过。

本地 `0.2.3` 候选另在“已有侧栏时进入生产表单”补充回归中复现了同类误关闭，已撤回候选而保留原制品。`0.2.4` 将自有菜单及表单挂入可唯一确认的宿主事件边界，并阻止关闭时的脱离节点点击继续冒泡；多个未知侧栏时拒绝选择任意容器。对宿主变换、裁剪和原生事件处理的真实观察仍须在实机只读验收中完成。

`0.2.5` 保留上述运行逻辑，增加有证据限定的 4.9.0 受控候选声明。旧版制品与摘要保留，不以同一路径覆盖历史候选。

`0.2.6` 修复激活时将现有折叠控件与业务按钮一并隔离、导致只读展开永久不可用的问题。仅带明确 `aria-expanded` 状态、可见且匹配当前 VM 的磁盘／网卡 header 可作为纯界面折叠项；点击前重新识别来源并核对完整 URL、导航代次、父名称、frame、header 和禁用状态。编辑与业务工具栏不享受这项例外，仍遵守原有隔离规则。
