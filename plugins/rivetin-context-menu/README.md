# Rivetin 对象右键菜单

`rivetin-context-menu` 的目标是将对象详情和侧边栏中的实际能力组织成分组右键菜单。右键虚拟机应直接提供电源、控制台、硬件、快照、迁移和管理等入口，不要求先打开侧边栏，也不只是转发行尾“更多”。其他对象与内部设备分别按其实际能力适配。

当前 `0.2.6` 为仅面向 **CloudTower 4.9.0** 的受控复验候选，已实现对象菜单、生产表单与共享资源操作服务桥的接入代码。描述文件仅列出 `towerBuilds: ["4.9.0"]`，不包含其他版本。**已有部分只读界面验收结果，内部折叠修复仍待真实复验，不是全功能已适配的正式版本。**

候选版本的依据是官方 4.9 API 契约、本地回归，以及主协调聊天在真实 4.9 环境完成的只读 API／身份权限链和 DOM 核验：虚拟机列表的行键与名称列、精确 sidebar 对象路由、唯一可见侧栏、标题和虚拟磁盘展开入口均得到观察。该依据只允许进入串行受控验收，不表示电源、编辑或其他虚拟机变更已在实机执行通过。

主协调聊天已在 `0.2.5` 实机只读检查中验证虚拟机行分组菜单、基本信息表单的本地草稿与取消，以及已有抽屉时的字段和取消行为；实际对话框位于视口内。内部磁盘“展开详情”未出现，该项未通过并已停用候选。`0.2.6` 的修复仍待真实复验。验收期间不点击资源变更确认；异常时停止并禁用候选。不能用安装成功、后台只读通过或本地模拟结果代替完整界面验收。

## 当前范围与缺口

- 已建立 67 项虚拟机动作的分组目录，区分正常关机、强制断电、快照恢复、新建恢复虚拟机等不同语义。
- 动作与对象 ID、状态快照、权限结果和实际子资源绑定；父虚拟机 ID 不会冒充磁盘、网卡、快照或 USB ID。
- 未取得状态、权限或可靠接口的项目显示禁用原因，不以静态菜单的存在表示可以执行。
- 菜单与表单分离。操作提供器先打开经校验的表单或确认流程；右键和读取状态本身不得提交业务变更。用户确认后，生产执行控制器重新读取身份、状态与能力，经共享服务桥提交一次并跟踪操作记录。
- 原生业务对话框的公开按 ID 调用契约尚未核验。官方 REST 支持多项资源操作，但不代表可以调用任意内置界面。实际原生适配器或独立业务表单仍需逐项接通。
- 主机、集群、虚拟卷、物理盘及其他设备的完整操作仍在盘点，不能将虚拟机目录视为全资源覆盖。

本地演示使用明确的模拟对象、模拟权限及内存状态，不连接真实 CloudTower。演示中的可见表单和确认不构成实际业务操作完成的证据。

## 接入边界

动作目录位于 `src/actions/catalog.js`，是纯元数据和状态计算，不执行网络请求。其公开操作来源为官方 [Node SDK v2.23.0](https://github.com/smartxworks/cloudtower-node-sdk/tree/v2.23.0/src/generated)，对应 CloudTower 4.9；本地较旧 API 技能仅作为线索。

插件内部的菜单提供器采用 `read(resource, {signal})` 和 `open(request, {signal})` 两阶段模型。生产提供器包装框架 `options.resourceActions(pluginId)` 的 `read` / `execute` / `task` 服务桥，认证、公开 API 白名单、持久幂等记录和任务回读由共享后端处理。子插件不读取认证 token、React 私有字段或内部 store，不猜控制台 URL。

当前共享后端首批支持 `vm.general.edit` 和 7 个 `vm.power.*` 动作。生产界面仅在服务端明确允许时启用；ROOT 以外账户的细粒度能力映射尚未验证时保持禁用。CPU、内存、快照、迁移和克隆已有部分表单及纯请求校验准备，不能视为服务端已支持。控制台仍未接通。67 个目录项不等于 67 项真实功能。

描述文件单独声明 `resource.actions` 权限，不能用 `ui.context-menu` 隐式取得资源修改能力。菜单和设置界面会说明确认后可能执行真实变更。操作状态为 `running` 时只查询同一操作记录；超时或结果不明不会自动重提，界面显示可定位的操作 ID。

具体接口、表单提交边界、取消规则和未接通范围见[操作提供器接入说明](docs/action-provider.md)。

真正的执行适配器必须在用户明确确认后再次校验对象、子资源、状态和权限，保留服务器最终鉴权。异步变更要跟踪实际 task 终态并重读对象；超时结果未知时不得自动重发。控制台返回的短期访问材料不得记录或保存。

功能配置使用 `/api/rivetin/v1/config`，键为 `rivetin-context-menu`，按框架草稿/保存机制持久化。新源码只使用 Rivetin ID、API、SDK、全局注册表与包格式，不读取、复制或迁移旧品牌配置。详见[配置契约](../../docs/rivetin-configuration.md)。

## 开发与验证

使用现有 Node.js 22 和框架锁定的 webpack、React、jsdom；不新增依赖。在本目录运行：

```powershell
npm test
npm run build
npm run package
npm run demo
```

描述文件为 `rivetin.json`，全局工厂为 `window.RivetinPlugins["rivetin-context-menu"]`，SDK 为 `RivetinSDK`。生产包使用 `rivetin-package-v1` / `rivetin-global-v1`，制品为 `release/rivetin-context-menu-0.2.6.rivetin.json`。构建不等于已上传、发布或部署。

本地演示仅监听回环地址 [127.0.0.1:43180](http://127.0.0.1:43180)。真实环境调查和验收必须与主框架协调独占窗口；不得在未明确授权的虚拟机上测试电源、迁移、编辑或快照恢复。

## 历史验收记录

旧品牌 `0.2.2` 的受控预发布验收仅通过了列表原生菜单路径，内部虚拟磁盘展开却使宿主侧边栏关闭，因此未通过。该验收结束时已禁用子插件并保留配置；这不表示用户此后的手工状态。旧包、原始截图和备份保留于本地忽略目录，不进入新包。新源码已增加宿主 outside-click/Escape 边界回归，本地修复不能冒充真实复验通过。

本地 `0.2.3` 候选另在“已有侧栏时进入生产表单”补充回归中复现了同类误关闭，已撤回候选而保留原制品。`0.2.4` 将自有菜单及表单挂入可唯一确认的宿主事件边界，并阻止关闭时的脱离节点点击继续冒泡；多个未知侧栏时拒绝选择任意容器。对宿主变换、裁剪和原生事件处理的真实观察仍须在实机只读验收中完成。

`0.2.5` 保留上述运行逻辑，增加有证据限定的 4.9.0 受控候选声明。旧版制品与摘要保留，不以同一路径覆盖历史候选。

`0.2.6` 修复激活时将现有折叠控件与业务按钮一并隔离、导致只读展开永久不可用的问题。仅带明确 `aria-expanded` 状态、可见且匹配当前 VM 的磁盘／网卡 header 可作为纯界面折叠项；点击前重新识别来源并核对完整 URL、导航代次、父名称、frame、header 和禁用状态。编辑与业务工具栏不享受这项例外，仍遵守原有隔离规则。
