# 原生操作入口提供器

自 0.4.1 起，右键菜单自动打开已适配的 CloudTower 官方原生对话框。旧 0.3 自建表单及资源写入服务桥停止作为生产路线，保留研究原件，不作为隐式后备。

> 当前状态（2026-10-29）：0.5.9 已在 CloudTower 4.9.0／框架 0.2.2 的新文档中完成原失败同路径真实复验：A 的 CPU 编辑器首开取消、B 只读身份导航、回 A 后准确 A 的新 CPU 编辑器再次打开并读取初值后取消；必要内存／盘／NIC、键盘／Esc／Shift 与当前桌面视口回归亦通过。保护后验通过并闭窗，020 仅在本次定向范围内 resolved。0.5.7 的实际失败、0.5.8 未通过独审且未部署的候选保留；不以新结果改写旧证据。

本次没有业务保存或字段修改，不代表业务任务完成、真实排队事件注入、其他语言／视口、独立生命周期切换或完整主机矩阵通过。真实排队取消仍待相应环境验证；本地源码、精确生产 bundle 和模拟浏览器证据单列。现场有 45 条宿主共享模块警告、0 条控制台 error，官方审计镜像权限拒绝未算成功。准确验证范围见 [README](../README.md#本次真实验证范围2026-10-29)。固定包 `bd33fce9ab2c664f8612cb873b4391fb53038c09cfd8bcfb40f9de141556f8ee` 未因文档更新改变字节，包内说明反映原冻结时点。

## 0.5.9 的退休侧栏恢复

当准确 VM 列表源行仍有效、当前唯一目标 sidebar 已退休时，只在白名单 VM 列表路由上移除 `sidebar` 参数。该导航不点击退休控件；必须观察到本次准确路由且全部旧面板从 document 卸载，然后重新核验原源行与选择节点，才使用官方行选择重建详情。新 A 的路由、名称、面板、入口和代次继续接受原有检查。未知路径、额外或重复查询、源行变化、外部导航、未卸载旧面板及移动的退休控件均不能通过此恢复。

旧面板、旧标题和旧叶子的 WeakSet 记录不清除，提供器或 bundle 重建也不能恢复资格。若恢复失败，菜单交接后仍展示本插件自己的可关闭诊断，30 秒内自动移除，停用时一并清理；不依赖插件中心处于打开状态。该提示不修改宿主弹窗或处理业务确认。

恢复只确认一次精确的原生 `oldURL→newURL` reset 边，且当前仍必须位于该 reset 地址；收到后还须经过一个有界事件轮次并完成旧节点卸载。其他具体导航边、重复边及排队的 B→reset／B→A→reset 仍立即取消，不能以最终 URL 相等掩盖外部跳转。缺少 URL 的 history 通知只等待原生边，不单独确认 owned reset；缺失该证明会按原期限停止。

## 生产边界

`src/definition.js` 默认创建 `createNativeActionProvider()`，不请求 `options.resourceActions()`。原生提供器没有资源 transport、参数字段或业务提交逻辑；不自行处理 VNC 凭据、CPU 拓扑、容量换算、NIC 索引、快照关系、迁移映射或任务终态。

官方界面负责参数、权限、状态限制、确认、执行和任务反馈。插件只能通过核实的原生导航／菜单／对话框入口接入，不能读取 React 私有字段、内部 store 或复制业务 handler，也不能按文字猜 API 或控制台 URL。

## 菜单内部协议

```js
{
  kind: 'native-ui',
  handoffBeforeOpen: true,
  bindSource(resourceDOM),
  read(resource),                  // 本地精确来源检查，不代表业务授权
  tree({ resource, data, locale }),
  open({ resource, actionId, snapshot }, { signal }),
  close(),
  stop()
}
```

`resource` 只含 type/id/name。绑定源从已识别的 DOM 取得，重新验证 ID、可见性、来源、同源链接和完整导航状态。不能根据同名标题寻找另一条记录。

`read` 返回的 data/snapshot 带内部一次性来源凭证，菜单在渲染时可复制显示数据，但交接时保留原凭证引用；新绑定、路由改变或停止使旧凭证失效。该凭证仅防止错对象导航，不是权限许可。`tree` 的 enabled 只表示可定位官方界面，不能当作可执行业务。

菜单须在调用 `open` 前卸载自己的节点，避免官方导航触发的 outside-click、路由及菜单清理互相干扰。`opened` 必须带 `surface: 'dialog'` 或 `'tab'`，表示已核验新原生对话框或活动快照页面；只定位对象不能返回成功。它不代表保存、执行成功或控制台已经连接。

0.4.2 的目录使用侧向级联子菜单，主目录保持不变；子层仍是整个对象菜单的 DOM 后代。关闭菜单会同时移除所有子层、hover 延迟和本插件的顶层弹出。悬停或键盘展开只显示菜单，不读取资源写接口或触发原生操作；点击叶子后仍走相同的一次性来源证明及最新状态核对，不绕过交接规则。

## 当前默认桥

### 0.5.0 原生菜单与入口扩展

`createNativeRowMenuAdapter()` 使用精确资源行与操作列的 More 控件建立本次会话。准备时仅展开原生 More 与子菜单，读取公开 DOM 元数据后关闭自己的菜单；不会选择业务叶子。`prepare()` 返回冻结菜单树和会话专属 opaque ID。`execute(id)` 重新定位相同来源、同一原生触发器及每层唯一路径，核对标签、类型、禁用状态和危险标识，最后点击一次官方入口。

Portal 必须有公开打开态，并且是本次唯一新可见弹层，具有匹配的 ARIA 关联或近邻位置证明。有显式 ARIA 引用时不允许退回几何猜测；其他弹窗、重复标签、节点替换或路由变化会拒绝操作。深度最多4层、条目最多200项，准备和执行各限时3秒；不复制官方 handler，不修改原生样式或拦截其生命周期。

新增资源列表的 UI 使用 `src/native/resource-menu.js`。所有子层仍位于同一宿主事件边界中；准备完成后重新检查边界连接状态。宿主移除菜单、对象来源变化、取消和停用都会释放会话。列表类型使用已核对的路由或同表完整表头组合；冲突时拒绝，不猜网络或快照路由。

虚拟机固定快捷目录的 45 个动作映射到 34 个 `nativeEntry()` 入口规格，多个动作可共享一个原生入口，并非 45 个独立对话框。六个新增配置编辑器分别验证对应原生对话框；只需要点击官方控件的操作返回 `{status:'handed-off',surface:'native-action'}`，官方菜单交接返回 `surface:'native-menu'`。这些结果不表示业务任务完成。恢复、重建和删除快照从精确快照行的原生菜单选择，不能把 VM ID 当成快照 ID。完整官方编辑菜单和 More 菜单保留入口，未提供等价 UI 的旧 SDK 研究动作不进入生产目录。

控制台只调用核实的原生控件；浏览器明确报告用户激活已过期时拒绝交接，不预开窗口、替换 `window.open` 或构造连接地址。配置字段和最终保存／确认均由用户在官方界面操作。

下面保留0.4.1基础桥的身份与对话框校验说明；其“未接通动作”边界以0.5.0注册表和上述交接定义为准。

0.4.1 自动定位精确对象后等待唯一原生面板，再点击已验证的区域编辑按钮或迁移向导入口。基本信息、CPU、内存共用基本信息区域编辑；磁盘和网卡使用各自区域编辑；查看快照切换原生快照页。它不自动点击保存、迁移提交、电源执行、添加／卸载设备、快照创建／恢复／删除等业务按钮，不读写字段，也不使用未知 popup。缺少可靠绑定时返回不支持，不再靠详情提示宣称交接成功。

0.5.5 要求初始面板具有精确、公开的对象身份；导航中退役的控件不会因标题更新、重新绑定或重建提供器而恢复资格，防止对象 A→B→A 往返时复用旧控件。面板还须与精确路由、当次来源及标题一致；存在多个面板、公开资源 ID 不符，或新导航复用了没有公开 ID 的旧标题节点，均停止。已有面板要求来源位于该面板，或精确列表行具有原生活动选中标记。名称仅作路由／来源身份的补充校验，不用于搜索同名资源。

区域编辑只查 `.extra-action` 直接父标题的唯一编辑按钮，不走全局编辑菜单。迁移要求目标工具栏文字／title 与指定图标同时匹配。点击前记录所有已有 modal；只有唯一新可见 modal、精确匹配预期标题才接受。已有对话框、未知菜单、并发新对话框、禁用或隐藏控件均不能成为成功交接。观察窗口已核实中文入口，原生英文标签仍需实机验证。

0.5.6 使用插件自有的 document Symbol 标识保存弱集合，在原生提供器、资源行适配器及同页面重新执行的插件脚本之间共享退休状态；新 document 独立建立状态，不读取宿主私有字段。跨对象导航还捕获列表操作列的控件、弹层根及其后代。行菜单准备、悬停、执行和关闭补偿均核对控件及祖先的退休状态，不能通过新行 ID、移动叶子或重建适配器恢复旧回调。真正新建的精确资源行与菜单可用，未失去归属的同对象隐藏菜单允许按原生流程再次展开。`.ant-dropdown-disabled`、`.ant-btn-disabled` 等公开禁用状态同样适用于编辑器、工具栏 opener、Details 页签及清理补偿，检测到禁用则不合成点击。

0.5.7 仅在无更具体表头证据的全局列表后备识别中，对 `/vms`、`/hosts`、`/vm-volumes`、`/disks` 允许单个可选尾斜杠。查询参数沿用原逻辑；未知根路径、额外子路径或重复尾斜杠不会因此取得全局列表身份。行 ID、侧栏子表隔离、退休控件与禁用状态判断不变。

一次交接默认最多等待五秒；源重绑、外部路由变化、可信用户输入、取消和停止会终止等待并清理临时观察器、定时器及输入监听。自动化到新对话框或活动快照页后立即结束，不继续操作原生表单。

`close` 只取消本插件工作，不关闭用户已有的官方页面／对话框。`stop` 清除插件监听器和临时节点。业务提交按钮永远留给官方流程中的用户确认。

## 验证

失败结果携带固定 `reason` 代码，由 `src/native/errors.js` 输出中英文原因和下一步建议。原生禁用、缺失或重复入口分别记录，不把禁用原因猜成权限不足。菜单准备通过当次调用的 `onFailure(reason)` 返回诊断，执行结果携带同一代码；不向界面传递原始异常、HTML、URL、对象内容或堆栈。已点击原生入口但无法核验预期窗口时，提示先检查窗口和官方任务，避免盲目重复执行；主动取消不弹失败提示。

本地测试覆盖无预开侧栏直接打开原生对话框、异步渲染、零资源 API／凭据及字段访问、同名和错 ID、旧面板复用、重复入口、外部／并发对话框、重绑及导航往返、菜单先卸载、停止清理、不自动点最终业务提交按钮。默认构建不加载旧业务表单提供器或资源写入桥。

真实验收分为定位、打开原生菜单／对话框并取消、最终业务测试三个环节，分别记录。打开和取消不能描述成业务操作成功；真实提交仍服从准确目标、备份、回退及排他窗口授权。
