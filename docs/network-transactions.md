# 网络事务与独立回滚：设计草案

状态：2026-10-29初版，属于本轮真实网络变更开发范围；不是已实现、已部署或已验证的承诺。0.2.5已完成框架升级与四既有插件保留验收，新工作页插件尚未安装；用户追加的贡献式通用UI入口由当前0.2.6源码优先落实，真实事务与独立回滚仍在本轮接续。只读页面或UI通用化不能将拓扑实装整项结项。本文不授权任何真实网络写操作。

## 已核官方能力与证据边界

官方[SDK兼容表](https://code.smartx.com/en/sdks/support_release)将SDK2.23.0对应CloudTower4.9；[Go SDK固定发布](https://github.com/smartxworks/cloudtower-go-sdk/releases/tag/v2.23.0)亦注明该产品版本。本轮下载官方[4.9.0 OpenAPI](https://code-site.smartx.com/en/specs/4.9.0-swagger.json)，`info.version=4.9.0`，577个路径，5,560,650字节，SHA-256 `8f7e6015b4b9fd39e7ac9b037b711df4165d92a7aa210189019366b9fbf11d89`；原件仅留本地研究目录，不进入包。

| 动作 | 4.9公开接口事实 | 当前可逆性结论 |
| --- | --- | --- |
| 改VDS物理网口集合 | `/update-vds`的data接受nicIds，另有name/work_mode/bond_mode | 是完整集合变更；原集合可作反向输入，但跨VDS搬移、任务中断、第三方并发及原生自动撤销语义尚未证明。不能仅凭字段存在启用应用 |
| 虚拟网络移到另一VDS | `/update-vm-vlan`的data包含名称/VLAN及QoS等，未提供目标VDS字段 | 不能把拖动意图直接伪装成已支持迁移；不以删除重建替代身份保持的移动 |
| 改NIC属性 | `/update-nic`接受usage、VF数量、MTU；未提供直接目标VDS字段 | 不属于当前物理口归属拖动接口，不顺手开放MTU/VF操作 |
| 管理网络配置 | `/update-cluster-network-setting`包含管理IP/网关等字段 | 硬排除，不纳入首批事务 |
| 原生网络确认/到期回滚 | 完整577路径中没有网络rollback/confirm接口；查到的rollback路径属于其他资源 | 仅能说公开4.9规范未提供此合同，不能推断私有接口不存在，也不能声称已有原生90秒保护 |

上述网络写接口返回WithTask集合。[官方异步任务说明](https://code-site.smartx.com/en/learning-api/mutation/task/)要求跟踪task_id并回读对象，HTTP成功不是终态。真实API写、任务失败/取消、网络回滚、跨VDS副作用均未测试；本轮四个first1只读样本不能补足这些证据。

## 必须先解决的独立执行身份

现有Tower transport借用当次浏览器用户认证；它不能保证注销、令牌失效或框架重启后的回滚。把原认证头放入journal、重新使用根密码或自动创建服务账户，均不是默认方案。

事务执行器须由显式配置的独立服务器身份提供，至少具备：来源与目标作用域可核验、无需原浏览器存活、重启后可重新取得认证、凭据不进入事务记录/普通config/API响应、可在应用前验证反向操作授权。journal仅存身份引用及验证结果，不存token或密码。优先采用有明确合同的原生自治撤销；当前公开规范没有提供该证据。

在独立身份与其最小权限尚未由准确配置及实测建立时，真实apply能力必须为false，返回明确`INDEPENDENT_ROLLBACK_IDENTITY_REQUIRED`，不能仍应用后声称“尽力回滚”。本地可以实施持久状态机和固定操作适配层、用明确fake执行器验证，但不把这些测试写成独立真实回滚已可用。身份的实际提供方式、权限与部署文件由主协调按具体方案安排，不因本草案自动扩大访问。

## 首批范围与硬保护

首批仅评估同集群、明确workload/migration用途VDS的物理网口归属集合变化；真实可逆性未证明前该操作仍禁用。虚拟网络跨VDS移动保留为本轮需求，须有正式支持的身份保持接口证据；没有证据时明确unsupported，而不是静默改为创建/删除。

任何管理/存储/系统用途VDS、混合保护网络、用途未知、共享于保护用途的NIC、身份或归属不确定、跨集群、非物理NIC、数据不完整/过期、在途原生任务、缺少可信依赖/连通性信息均拒绝应用。布局与本地草稿不触发真实动作。VDS名字、NIC名字、同VDS或A/B标签不授予可编辑资格。读模型revision不是原生CAS。

写能力必须独立于inventory.read表达；不会借只读权限开放网络变更。新增权限/元数据的旧市场解析影响需用准确旧解析器验证并单独解决，不能为了旧reader载体而省略权限或静默放宽语义。

## 最小持久状态机

每事务唯一UUID operationId，准确ROOT操作者、cluster、固定有界操作集与审阅摘要。plan只读预检返回有界preimage指纹/能力及过期时间；apply要求同一操作者、原plan摘要、明确ack及唯一请求ID。写入前重新读取真实对象、原生任务和权限，比较完整受影响前像；框架自有对象锁只防框架内并发，不声称防止外部管理员修改。

持久状态：planned → preparing → applying → awaiting-confirmation → confirmed；回滚路径rollback-requested → rolling-back → rolled-back。失败分别保留rejected、apply-unknown、rollback-unknown、conflict或manual-intervention，不能统称失败已回滚。

在任何原生请求之前，以持久journal封存原像、准确正/反向动作、操作者/独立身份引用、请求意图及资源锁；每个请求紧前再落唯一attempt标记。返回后记录原task_id/资源身份，持续有界查询原任务并回读真实配置。若请求已发但未能可靠取得task_id或持久写未知，不重发变更；转unknown并用原对象/任务证据调和。新的operationId不绕过旧不确定锁。

确认截止由服务器在应用前持久化，不能由浏览器计时延长。90秒包括应用过程，未确认不表示应用已完成；到期先核原任务终态和实际对象，再按已核执行能力撤销。确认是服务器持久终态，必须在截止前、正向终态和准确postimage核对后接受；状态转移及deadline由服务端锁定。客户端取消只停止等待，不取消、确认或删除服务器事务。

回滚只在当前对象仍匹配该事务准确postimage、没有第三方冲突且独立身份可用时发送准确反向操作。若第三方已改字段或任务仍未知，不覆盖它；标conflict/manual-intervention。原生反向任务同样跟踪终态并回读preimage，不能仅凭提交成功报告rolled-back。不承诺多个原生操作的全原子性。

启动恢复扫描本框架持久事务：planned不执行；在截止前恢复原task_id查询；已过期的未确认项走独立回滚核对；未知attempt不盲重放。系统时钟回退不能重新授予完整90秒，时间异常按不安全状态处理；持久化损坏/磁盘满/多进程冲突停止新应用，保全原记录。框架进程完全不可用期间无法承诺本进程自行回滚，因此有硬时间保证须依赖另有已验证、独立于此进程的原生/外部执行机制；单Node定时器不满足该保证。

## 开发切片与验证

1. 0.2.5工作页、context、只读DTO及本地草稿快速固定；明确不是整个拓扑任务完成。
2. 本轮继续实现能力矩阵、plan/preflight、持久journal/排他锁、重启/unknown调和和固定真实操作适配层。缺独立身份或原生可逆证据时真实apply失败关闭，但上述基础测试可以完成。
3. 与TOPO统一capabilities/plan/apply/confirm/rollback/status的精确HTTP与客户端合同，不使用config PUT。UI显示服务器deadline/task/状态与实际操作能力，断线只回读原operationId，不重放。
4. 专项覆盖浏览器关闭、用户token失效、进程重启、时间异常、native task失败/超时/响应丢失、journal写失败、第三方并发、保护NIC与重复请求。模拟与真实故障分别记录。
5. 设计和准确固定候选经审查后，由主协调列具体真实对象、前像备份、影响、独立执行身份、回退/停止条件并安排测试窗口；当前没有真实写入授权。

尚待明确的实际能力是独立身份与进程外到期保护，以及4.9物理NIC跨VDS操作的副作用与可逆性。它们是本轮需要落实的接口/部署事实，不伪装成已实现功能，也不通过前端倒计时补齐。
