# Rivetin 0.2 系列验证范围

以下按固定候选记录验证范围。0.2.0 段落为历史记录；2026-10-29 的 0.2.2 受控验收见文末，不以新结果覆盖旧失败或旧版本限制。

本记录固定对应 2026-10-28 的 0.2.0 候选制品及受控开发测试环境验收。测试数量和部署状态属于该候选，不能代替当前工作树的验证，也不代表所有 CloudTower 构建、平台或生产环境均已验证。

## 本地验证

- 框架冻结候选：584 项测试通过，零失败、零跳过。
- Tower 端部署逻辑：66 项 Python 测试通过；Go 测试和 `go vet` 通过。
- 六个平台组合完成构建及格式、架构、内嵌资源、`CGO_ENABLED=0` 和 `-trimpath` 核对。Windows amd64 的版本、中文帮助、英文帮助和许可证命令在空 PATH 下实际运行通过；其余五个组合没有原生执行证据。
- 实际服务归档的 42 项完整性记录逐项匹配；提取副本中的文件被修改后检查失败，恢复原字节后检查通过。这是本地测量基线，不是发布者签名或独立信任根。
- 中英文组件状态界面已在本地检查；实机界面验收使用中文。

## 实机升级

在 CLI 精确 profile 对应的 CloudTower 4.9.0 构建上，先备份框架代码、完整配置与 Island，再通过 Windows amd64 便携式 CLI 从 0.1.5 更新到 0.2.0。安装器确认完成后，分别在停用和重新启用阶段进行独立后验。

14 项检查通过，覆盖代码及 Island 固定字节、专用资源变更范围、官方 Pod 状态、配置与连接信息、数据文件及权限、兼容性停用状态，以及虚拟机配置、磁盘和任务保护。官方 Pod 状态和重启次数保持不变。未新增主机命令、SSH 审批或采集计划。

验收工具针对新增 `disabledReason` 和公开的可选 SMTX 观察字段做了显式 schema 适配；原始备份和失败记录保留，没有通过删字段比较或改写旧记录使检查通过。

平台内虚拟机快照的数量和内容不属于框架或子插件部署门禁，不为此查询或比较快照清单。这不授予创建、修改或删除快照的权限，也不替代框架自身的文件备份。

## 界面及服务

- 实机插件中心显示框架 0.2.0、“组件状态”、兼容性说明及维护入口。
- 代码完整性、存储、操作日志、更新源等已检查项目显示实际结果。无法独立观测的 Island、网关及尚未端到端验证的 API 保持未知。
- 实机支持包 API 返回的 gzip 文件已核对大小、SHA-256 和 JSON 格式；未自动上传支持包。
- 官网 v4 目录的 HTTPS 读取可用，当前为空目录。原 v3 目录及三个旧包保留；旧 0.1.5 实机市场仍能读取三个发布条目。空 v4 不代表新版子插件已经发布。

## 尚未完成

旧兼容性声明的四个子插件保持停用；新声明版本的实机更新与恢复尚未验收。该候选验收时，右键菜单仍需完成旧 DOM 复用问题的修复、独立审查及实机复测，不能恢复原版本作为替代。后续源码进展与验证边界见 [原生操作入口提供器](../plugins/rivetin-context-menu/docs/action-provider.md)。

SSH 设备策略 v2 的后端与迁移、有效真实 SMART 健康样本及跨日计划、真实 BMC 网页自动登录均未完成。Web 修复只处理文档规定的框架元数据和缓存范围，不重建 Deployment、Ingress、代码或 Island；本轮没有在实机执行修复或重置操作。

当前固定制品仅用于受控验收；仓库源码、官网目录、公开安装器下载和子插件发布是不同交付步骤。
