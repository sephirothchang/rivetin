# 0.1 验证范围

核验日期：2026-10-28。本文固定记录当时 0.1 系列 Rivetin 制品与更早开发版本的历史验收；文中的版本、数量、部署状态及未覆盖项均属于该轮次，不代表当前源码或环境状态，不代表厂商认证或不存在未知缺陷。当前受控测试实例为 CloudTower 4.9.0；其他版本未获安装、启用兼容声明。

## 该轮次自动化验证

- 框架 0.1.1：本次发布范围的 390 项测试通过，覆盖生命周期、独立配置、认证与 Origin、版本门禁、紧急禁用、草稿保存与退出、SSH 凭据、指纹确认及认证预检、命令授权撤销、SMART 手动采集去重、数据净化与持久化。未接入运行包的实验性资源适配器不计入本次发布范围。
- 便携式 CLI：实际嵌入 0.1.1 包的 Go 全量测试与 `go vet` 通过，Python 54 项通过；依赖校验通过。Windows、Linux、macOS 的 amd64/arm64 六种产物交叉构建成功，格式、架构、摘要、trimpath 与 Linux 无动态加载器检查通过；Windows amd64 原生 version/help/licenses 在空 PATH 下通过。交叉编译不代表六平台实机安装验收。
- 各子插件的本地回归与界面验证范围见其 README。模拟服务、回环 SSH、契约测试均不能代替真实 BMC、主机或资源变更验收。
- 公开内容检查通过；另须人工检查差异、历史及制品。环境原始输出、备份、凭据和截图只存本地，不随源码或发布包交付。

## 该轮次真实环境验收

Rivetin-only CLI 已完成基础版本及 0.1.1 的受控真实升级。每次升级前备份代码、数据、部署资源与 Island，固定制品摘要，验证恢复工具的离线预检；没有执行快照恢复。

### 框架 0.1.1 与单盘只读联调

- CLI 从 0.1.0 升级至 0.1.1 用时约 25 秒，首次运行状态回读收到 503，下一次成功。仅允许明确的版本元数据升级，既有 SSH 0.1.1 状态及全部功能配置保留。关闭阶段 29 项、恢复原运行开关后 30 项保护检查通过；官方 Pod、其他 Island、部署代码及页面资产均按冻结基线核验。
- 既有全局 SSH 凭据通过 `keep` 保留，新增唯一审核目标与设备映射。真实未认证握手指纹匹配独立确认值，认证预检成功且不执行命令。临时注册的 `host.identity` 手动执行一次成功，随后卸载并归档保留证据。
- SMART 由 0.1.1 升至 0.1.2，配置保留。真实页面“立即采集”提交一次，期间按钮禁用；命令非零退出，后台保存一条失败历史，页面显示健康未知。固定错误码为 `SSH_REMOTE_COMMAND_FAILED`，尚不能区分工具、参数或虚拟磁盘支持问题；没有追加命令或自动重试。
- 单一设备的 86400 秒计划已获明确批准并登记；未等待一天或人为加速计划，不能声称每日任务已真实执行。采集后 37 项收尾核验通过，确认只存在一条手动任务、一份审批、一条未来计划及一条失败历史；仍未取得有效 SMART 指标。失败任务结束后，0.1.2 需点击“重新读取”刷新失败历史，此按钮仅读取已有记录，不再次采集。
- 首轮结束后，另获明确批准追加同一命令一次用于诊断。捕获到 smartctl 7.1、有效设备信息 JSON 与退出码 4，stderr 及 JSON 消息列表为空；未返回 SMART 健康或属性数据。按 [smartmontools 官方手册](https://github.com/smartmontools/smartmontools/blob/main/src/smartctl.8.in)，该位表示 SMART／ATA 命令失败或 SMART 数据校验错误，不能直接解释为磁盘损坏。设备模拟层支持不足是推断，尚未确认。追加诊断仅一次、没有自动重试；12 项只读收尾检查确认原配置、凭据库、其他组件及每日计划到期时间不变。原始输出只存受限备份，不进入仓库。
- SSH 例外卡片及预检 UI 的中英文、本地草稿与失效行为已验证。真实页面核验及所有原始证据仅保存在受控本地目录，不进入仓库或发布包。

### 基础版本的前序验收

- CLI 升级约 24 秒完成，随后回读服务与 Island 资源。部署代码及前端资源逐文件匹配冻结制品；CloudTower 原生 Pod 的 spec、UID、就绪状态和重启次数保持不变，其他 Island 保持原状。
- 原有插件配置和启用状态保留。SSH 子插件从 0.1.0 升至 0.1.1，再确认服务端版本与配置；升级没有添加凭据、批准命令或启动主机连接。
- 真实只读接口验证覆盖虚拟机、主机、集群、物理盘、SSH 目标清单和安全连接摘要。SMART 未绑定时明确拒绝，不返回伪造指标；已停用插件不能读取其受控资源接口。临时验证插件已卸载，残留测试文件已移入备份区。
- SSH 页面已显示全局、集群例外和主机连接编辑。真实库存选择、主机地址填充、未保存退出三选与丢弃均通过。没有在真实环境提交凭据；AES-256-GCM 的可逆存储、保留/替换/清除、权限收口和保存撤销授权由本地服务链回归覆盖。
- SMART 0.1.1 已安装启用。主机和集群两种物理盘页面的挂载、切换、未绑定提示、停止清理及原生内容恢复通过真实页面检查。尚未配置可信设备映射或批准采集，没有真实 SMART 样本或每日历史验收。
- 右键菜单已进入受控实机验收。无侧栏的虚拟机分组菜单和基本信息表单、仅本地输入后取消、已有详情抽屉中的输入/取消、停用清理通过。实际对话框位于可视区域，原生抽屉保持正常。0.2.5 曾因旧控件隔离导致内部磁盘展开入口缺失，修复后的 0.2.6 已实机验证热启、展开和收起，均保持原生抽屉与 URL；跨对象菜单的表单身份也与点击行一致。业务编辑仍受原有隔离，不能将只读界面验收视为真实资源写入验收。
- 虚拟机配置与验收前回读一致，插件操作审计没有资源执行事件。没有提交虚拟机电源、编辑、迁移、磁盘、网络或其他业务变更；真实资源写入不在本轮验证范围内。

## 早期历史验收

此前开发版本曾验证 IPMI 链接、服务端配置、匿名与错误 Origin 拒绝、API/Web/CLI 紧急禁用与恢复，以及基础中英文界面。该轮次 IPMI 0.1.2 仅启用登录页跳转；MegaRAC 自动登录和其他厂商 Redfish 只完成本地模拟或协议契约验证。

原生审计写入接口在该测试版本要求系统用户，获准管理账户仍被拒绝。Rivetin 保留自己的操作日志与原生镜像交付状态，没有借用内部系统身份或改数据库。非管理员分支由本地自动化覆盖，未为实机测试创建额外账户。

## 已知边界

故障隔离仍为 TODO，不宣称第三方插件具有沙箱。框架自身 Web 自更新、自动配置 schema 迁移、后端可执行子插件、发布者签名、日志自动轮转和多 Pod 分布式调度尚未实现。框架更新使用便携 CLI，schema 版本不匹配拒绝安装。

网络拓扑的浏览器验收继续待办。有效 SMART 采样、BMC 自动登录及资源写入不能因其他测试通过而视为已验证。右键菜单后续按原生界面入口设计推进，未发布的自定义表单与资源适配实验不作为已交付能力。
